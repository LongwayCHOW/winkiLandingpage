# BLOG-MATERIAL 素材模板总入口

> 用途：为每个 app 的高质量博文收集「只有开发者本人能提供的素材」（真实体验、数据、截图、故事）。
> 机制：你（开发者）按需填写某个模板 → 我用 `/zac-seo` + `/seo-writing` 把素材翻译、组织成英文博文。
> 原则：**素材越真实、越具体，博文 E-E-A-T 越强**。宁可少而真，不要多而虚。

## 使用流程

0. **看进度**：先打开 `docs/CONTENT-TRACKER.md`——它是总看板，标记哪些素材已给、哪些博文已产出。
1. **选模板**：根据想写的博文类型（或追踪表里待写的项），打开对应模板文件。
2. **填空**：按模板里的问题回答，中文即可，想到哪写到哪，不需要通顺。
3. **存素材**：每 app 建一个素材文件，如 `docs/素材/app-chronicle-对比.md`（建议按模板名 + app 命名）。
4. **回填看板**：在 `CONTENT-TRACKER.md` 里给对应素材格子打勾。
5. **给我**：把素材文件路径给我（或直接贴内容），我会：
   - 用 `/zac-seo` 校准关键词与结构（每篇 2-4 个核心词）
   - 用 `/seo-writing` 规范英文（title/description/可读性/内链）
   - 用「英文诗意地」重写，保留你的真实语气

## 通用素材（所有模板都可能用到，可一次提供）

以下素材与具体博文无关，提前准备好随时可用：

- [ ] **每个 app 的硬数据**：下载量、日活/月活、评分、评价数（真实数字，哪怕很小）
- [ ] **真实截图**：每个 app 2-3 张实际界面截图（主界面 + 特色功能），放在 `src/assets/images/post/<app>/` 下
- [ ] **真实用户反馈**：App Store / Google Play 真实评价原文（含评分和名字）、邮箱/社媒收到的反馈
- [ ] **产品事实**：平台、定价、订阅规则、隐私说明、联系邮箱（尤其 DeliSeek / VocalTrans 的 iOS 是否规划中）
- [ ] **一张真实的开发者/产品照片**（非必须但很有力）：能放到 About 或作者栏

## 写作约定（我会遵守，你只需提供素材）

- 每篇博文聚焦 **2-4 个核心词**，不堆砌（zac-seo）
- 内链到对应 app 落地页（Hub-Spoke）+ 2-3 篇相关旧文（seo-writing）
- 结尾带 `<AppDownload>` 下载组件（如适用）
- 发布前对照 `BLOG-CHECKLIST.md` 自查
