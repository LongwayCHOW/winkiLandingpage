## 核心素材（请围绕一个"冲突或取舍"展开）

1. **一个真实的技术挑战**：
A、大量的手机传感器的权限没有被系统开放给其他app使用  
B、不同品牌、配置的手机之间存在很多的差异，几乎无法用一个app产品覆盖所有的app的传感器设计  
C、不知道是系统缺陷，还是传感器的硬件缺陷，对硬件传感器的调用常常存在功能上的残缺

2. **你尝试了什么方案**？
A、我尝试了有系统给出陀螺仪方向的方案，发现经常漏信号，数据链中断
B、我尝试了通过读取系统其他ui的方向的变化来识别陀螺仪的方向变化，发现这个需要用户开启系统的自动旋转
C、最后，我尝试自己开发一个功能来接收设备陀螺仪发出的信号，这次成功了，但是我发现在方向上有问题，有的设备有正放的方向数据输出，有些设备没有

3. **最终怎么解决的**？最后选了方案c，让手机可以通过旋转方向来获得计时的启动、停止、更换预设的计时分总数等功能，不要需要再精细操作手机来控制计时器，just flip 一下就好
4. **一个设计取舍**：为什么选 C 放弃 AB？原因是：由app直接接收传感器的数据，数据链更稳健，在更多其他品牌、不同硬件配置的设备上运行成为可能，不依赖差异性极大的设备系统
5. **过程中学到的教训**（对同行或用户都有价值的思考）：要学会一开始就要抓住核心，直接通过最短的路径获取想要的信号
