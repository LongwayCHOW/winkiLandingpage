# 博客发布前检查清单（BLOG-CHECKLIST）

> 每次发布一篇博文前，对照本清单自查一遍。来源：`seo-writing`（写作规范）+ `zac-seo`（实战最佳实践）。
> 目的：内容事实与技术发布双重质量门。技术问题不能仅凭模板保证，必须运行构建、SEO 回归和浏览器检查。
> 当前整改状态见 `docs/seo_remediation_todo_2026_10_23.md`；历史诊断不是当前完成状态。

---

## 一、关键词与结构（seo-writing）

- [ ] **搜索任务确认**：明确读者要完成的任务；候选词需产品能力、目标地区 SERP 和可用 GSC 数据支持。广告 Competition 不是 SEO 难度。
- [ ] **核心词位置**：主关键词出现在
  - [ ] Title 简明准确；50-60 字符只作编辑参考，不是 Google 硬限额
  - [ ] 第一段前 100 词
  - [ ] 至少一个 H2
  - [ ] 全文自然出现（不堆砌）
- [ ] **Meta description**：专属、自然、符合正文；不为固定字数凑词或强制下载 CTA
- [ ] **URL slug**：新页用描述性小写路径；已有 URL 不因改标题而迁移
- [ ] **标题层级**：H2 主分节、H3 子节，不跳级；H1 只出现一次（系统生成）
- [ ] **可扫读**：段落 ≤3 句；关键信息用列表；长文（>1000 词）加目录或 TL;DR

## 二、链接（seo-writing + zac-seo）

- [ ] **上下文内链**：指向主产品与真正相关内容，数量由用户任务决定；共享文章组件已有主产品入口
- [ ] **来源**：可验证声明有对应官方来源/原始材料；引用数量不是目标
- [ ] **锚文字描述性**：准确说明目的地，不重复硬塞关键词；内部链接不加 UTM

## 三、内容质量（zac-seo 重点）

- [ ] **每篇聚焦一个任务**：不因关键词数量而堆砌或拆薄页
- [ ] **真实第一手经验（E-E-A-T）**：有自己的使用体验、数据、感受；不空泛复述
- [ ] **对用户有价值**：为解决问题而写，不是为排名而写（有用内容更新标准）
- [ ] **无堆砌痕迹**：没有为凑关键词的别扭句子、重复短语、无关词列表

## 四、中英混排（实战补充）

- [ ] **无中文标点**：全文用英文标点（`:` 而非 `：`，`,` 而非 `，`，`"` 而非 `“”`）
- [ ] **无全角字符残留**：数字、括号、引号均为半角
- [ ] **英文排版**：`&` 写成 `and` 或使用 `&amp;`（HTML 中）；破折号规范

## 五、图片（seo-writing）

- [ ] **图片确实有用**，新增资源使用下划线命名；真实 UI/测试不得用生成图冒充
- [ ] **ALT 文字**：描述实际图像信息；装饰图用空 ALT，不强制加关键词
- [ ] **尺寸与体积**：依据显示宽度、currentSrc 和可读性设置；不能以所有图片 <100KB 一刀切

## 六、发布前最终核对（seo-writing Final Checklist）

- [ ] 标题、H1 与正文准确回答同一搜索任务，不机械强制词的位置
- [ ] Meta description 已写 ✓
- [ ] URL slug 已优化 ✓
- [ ] 内链已加 ✓
- [ ] 外链已加 ✓
- [ ] 图片有 ALT ✓
- [ ] 可读性可接受（无复杂长句）✓
- [ ] 无重复内容 / 薄内容 ✓
- [ ] 当前版本、价格、用户引语、研究/测试、竞品事实均有真实依据；未知不能 AI 补造
- [ ] 作者/开发者关系明确；过期活动标历史，实质修订才更新日期
- [ ] `npm run build`（含 `check:seo`）通过；JSON-LD 与可见内容一致，不为富结果伪造评分
- [ ] 无 JS 正文与下载可用；移动/键盘操作通过；客户端导航后事件不重复
