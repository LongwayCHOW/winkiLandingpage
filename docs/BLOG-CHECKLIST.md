# 博客发布前检查清单（BLOG-CHECKLIST）

> 每次发布一篇博文前，对照本清单自查一遍。来源：`seo-writing`（写作规范）+ `zac-seo`（实战最佳实践）。
> 目的：**内容层面的质量门**。模板层面的技术 SEO（title 格式、schema、URL）已由落地页模板与 Astro 构建保证，不在此清单内。

---

## 一、关键词与结构（seo-writing）

- [ ] **核心词确认**：开写前确认 1 个主关键词 + 3-5 个相关长尾词（来自关键词集群表）
- [ ] **核心词位置**：主关键词出现在
  - [ ] Title（50-60 字符，靠前）
  - [ ] 第一段前 100 词
  - [ ] 至少一个 H2
  - [ ] 全文自然出现（不堆砌）
- [ ] **Meta description**：150-160 字符，含核心词 + CTA（"Download…" / "Learn more…"）
- [ ] **URL slug**：短，只用核心词，小写 + 连词符
- [ ] **标题层级**：H2 主分节、H3 子节，不跳级；H1 只出现一次（系统生成）
- [ ] **可扫读**：段落 ≤3 句；关键信息用列表；长文（>1000 词）加目录或 TL;DR

## 二、链接（seo-writing + zac-seo）

- [ ] **内链 2-3 个**：指向相关旧文 + 1 个指向对应 app 落地页（Hub-Spoke 汇聚权重）
- [ ] **外链 1-2 个**：权威来源（官方文档 / 维基 / 权威评测）
- [ ] **锚文字描述性**：用关键词作锚文字，禁止 "click here" / "read more"

## 三、内容质量（zac-seo 重点）

- [ ] **每篇聚焦 2-4 个核心词**：不试图覆盖一堆长尾词而堆砌
- [ ] **真实第一手经验（E-E-A-T）**：有自己的使用体验、数据、感受；不空泛复述
- [ ] **对用户有价值**：为解决问题而写，不是为排名而写（有用内容更新标准）
- [ ] **无堆砌痕迹**：没有为凑关键词的别扭句子、重复短语、无关词列表

## 四、中英混排（实战补充）

- [ ] **无中文标点**：全文用英文标点（`:` 而非 `：`，`,` 而非 `，`，`"` 而非 `“”`）
- [ ] **无全角字符残留**：数字、括号、引号均为半角
- [ ] **英文排版**：`&` 写成 `and` 或使用 `&amp;`（HTML 中）；破折号规范

## 五、图片（seo-writing）

- [ ] **至少 1 张题图**，文件名描述性（`seo-best-practices-2026.png`）
- [ ] **ALT 文字**：描述图片 + 含相关词（不堆砌，一次即可）
- [ ] **体积**：压缩至 <100KB（或依赖 Astro 图片优化）

## 六、发布前最终核对（seo-writing Final Checklist）

- [ ] 核心词在 title、H1、前 100 词、一个 H2 ✓
- [ ] Meta description 已写 ✓
- [ ] URL slug 已优化 ✓
- [ ] 内链已加 ✓
- [ ] 外链已加 ✓
- [ ] 图片有 ALT ✓
- [ ] 可读性可接受（无复杂长句）✓
- [ ] 无重复内容 / 薄内容 ✓

## 说明

- **成本**：本清单是静态参考，检查时只读刚写的那一篇（几千字符），不会触发整库重读。
- **时效**：算法与搜索规范持续演进（有用内容更新、E-E-A-T、AI 内容标注），定期回到 `/zac-seo` 核对最新章节。
- **落地页**：此清单用于博客；落地页遵循 `mobile-app.astro` 模板（已内嵌结构最佳实践）。
