# 为什么开发photo_swipe_cleaner

> **用途** 在我开发这个产品的时候，市面上的相册整理/清除app几乎都是一下类型：
1、图片对比，找出相同的图片，批量图片清除
2、按文件类型、获得来源进行批量图片清除
3、找错所有的相似图片，按相似性进行批量图片清除
4、按日期整理图片，按日期进行批量图片清除
5、图片清理功能附属在手机存储空间整理app中作为一个模块存在
似乎人们的相册是无关紧要的垃圾，被丢进一个名为“图片清理”全部burn up 掉，没有一个app认为相册是用户珍贵的回忆，需要小心地处理每一张照片

于是，将由我来开发一个“一张张进行整理”同时兼顾“速度”的相册整理软件

## 核心素材（请围绕一个"冲突或取舍"展开）

1. **一个真实的技术挑战**：我们如何设计图片的清理过程的交互重点，将决定这个app能否达到我们的设计初衷。
2. **你尝试了什么方案**？
A、批量选中功能：我们尝试了在图片的collection 展示界面从单张到4张一行的展示效果，最后我暂定了按照3张图一行来兼顾用户可以比较清晰地看清楚的单张图片的内容不会导致被误选，又比单张和2张一行更有显示效率
B、我选择了 10，000 张图片作为测试的样机相册，我不断尝试了不同图片的加载方式和压缩缓存技术架构，都很容易造成内存因为缓存过大而导致app闪退或者卡顿，或者会导致已经删除的图片在collection序列上还显示图片占位等等bug，尤其是中低配置手机上的表现更差
C、我们尝试求助系统底层的相册api支持，发现能获得的支持非常少
D、回到非批量删除，在处理单张照片的交互时，我们尝试了传统的“点击删除-弹出确认框-点击确认-直接删除”以及”长按呼出删除确认框-点击确认-直接删除“等等交互手段，最后我发现可以借鉴”tinder“的交互，”左滑右滑“来标记图片是删除还是保留，然后提供redo和undo，以及图片不再直接删除，而是发送到回收站作为安全清除选项，在处理单张照片，在”交互效率、安全删除”上达到一个完美的平衡
E、接下来，就是持续需要解决一个丝滑的交互的问题

3. **最终怎么解决的**？找到了一个交互丝滑的卡片交互封装库，它甚至让我想起了我的 palm pre 手机，以及经过我努力的优化，我暂时让 10,000 张图片的加载不再崩溃了
4. **过程中学到的教训**（对同行或用户都有价值的思考）：一个好的初衷需要找到一个需要它的人，不然还是和这个 app一样无法赚到钱 lol
