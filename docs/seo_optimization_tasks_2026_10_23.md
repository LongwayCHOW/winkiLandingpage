```text

先读 AGENTS.md、docs/seo_diagnosis_2026_10_23.md 以及本任务书。
本轮只执行我指定的任务 ID，不自行开展其他任务。

开始时：
1. 读取相关源码和 git status，保护已有改动。
2. 复核诊断是否仍成立，不把历史文档中的结论当成现状。
3. 简述修改范围、依赖、人工确认项和测试方式。

- 不迁移现有 URL、站点框架或主域名，不改 ~/ 别名。
- 不编造功能、定价、评分、下载量、用户故事或搜索量。
- 未知的产品事实标 unknown，等待确认；可以继续做不依赖它的工作。
- 不擅自改 Cloudflare/商店/GA/GSC 后台，不提交或推送，除非明确授权。

- 列出修改文件、对应诊断编号、测试命令和结果。
- 明确未完成与需要后台验收的部分。

```

## 1. 执行顺序

```text
T01 数据基线 ───────────────────────────────→ T14 效果复盘
T02 产品事实 → T03 品牌/信任 → T08 产品内容 → T10 内容试点
            → T04 旅行页修订
            → T07 下载与测量
T05 模板清理 → T06 URL/索引 → T13 发布质量门
T09 内链可与 T08 同步；T11 schema、T12 性能在前置事实明确后实施
```

代码与内容可以分工，但修改同一个文件时要串行整合，尤其 `navigation.ts`、产品页、`Layout.astro` 和 AppDownload。

工时只是粗略工程预算，不包含产品核验、素材等待、后台权限和搜索引擎生效时间。

## 3. 附件使用说明

- `seo_url_inventory_2026_10_23.csv`：216 个本地构建 HTML，标明哪些有线上 GET 验证；`not_tested` 不能当 200。`canonical_raw` 保留原始值；robots 指令不是实际 Google 收录结果。
- `seo_keyword_source_2026_10_23.csv`：2,667 条有数值月量的原始关键词记录，保留 sheet 和单元格；不是已经批准的目标词表。`web_seo_difficulty=unknown_not_ads_competition` 是刻意保留的未知值。
- 对关键词附件的下一步是人工/规则辅助的意图审查、产品事实匹配和目标地区 SERP 核验，不是直接批量生成页面。
